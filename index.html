How it works

The architecture nobody else uses.

Most docs tools either mirror the docs into a repo (stale between syncs, ~100 MB clones, redistributes content that isn't theirs) or run an MCP server (another process, network round-trips, answers that flood your context). This does neither.

01 · every 3 hours

GitHub Actions builds the map

CI reads Anthropic's two llms.txt files and two sitemaps, then commits a page manifest and a prose-free search index. Metadata only.

runs on: github.com
02 · each session

Your machine syncs the map

A SessionStart hook hard-syncs the ~3 MB metadata repo and re-fetches only the pages that changed, in the background.

lives in: ~/.claude-code-docs/
03 · on demand

Claude reads the real page

Search hits the index in shell. Claude fetches only the pages it needs, .md straight from Anthropic's servers, into a local cache.

fetched from: platform.claude.com · code.claude.com

The guide has a recipe for exactly this: a PreToolUse hook with matcher Edit|Write that runs a script. hooks-guide → Block edits to protected files

The script must exit 2 to block. The reference is explicit that exit 1 is only a non-blocking error, and stderr becomes Claude's feedback. hooks → Exit code 2

The user wants this shared with the team, so it goes in .claude/settings.json, the project-scoped file that can be committed. hooks-guide → Configure hook location

Path via "$CLAUDE_PROJECT_DIR" so it resolves on every teammate's machine, and the script must be executable. hooks-guide → Register the hook

PreToolUse hooks fire before any permission-mode check, in every mode including bypassPermissions, so a blocking hook is policy users can't switch off. Worth telling the user. hooks-guide → Hooks and permission modes

write.claude/hooks/protect-files.sh
#!/bin/bash INPUT=$(cat) FILE_PATH=$(echo "$INPUT" | jq -r '.tool_input.file_path // empty') FILE_PATH="${FILE_PATH//\\//}" # normalise Windows separators, as the guide does PROTECTED_PATTERNS=(".env" "package-lock.json" ".git/") for pattern in "${PROTECTED_PATTERNS[@]}"; do if [[ "$FILE_PATH" == *"$pattern"* ]]; then echo "Blocked: $FILE_PATH matches protected pattern '$pattern'" >&2 exit 2 # exit 2 = block; stderr becomes Claude's feedback fi done exit 0
bashchmod +x .claude/hooks/protect-files.sh
edit.claude/settings.json
+ "hooks": { + "PreToolUse": [{ + "matcher": "Edit|Write", + "hooks": [{ + "type": "command", + "command": "\"$CLAUDE_PROJECT_DIR\"/.claude/hooks/protect-files.sh" + }] + }] + }

What you're looking at

The plugin commits two files. A manifest maps every page to its official URL, category, and content hash. A search index holds each page's title, headings, and a lossy bag of stemmed terms with counts.

  • Lossy on purpose. You cannot rebuild a page from the index. That is what makes it safe to commit.
  • Same data, different engine. Inside Claude Code the search runs in shell with jq. Here it runs in your browser. The hits come from identical files.
  • Every result is a real link. Click one and you land on Anthropic's page, not a copy.

  }
}

Safety

Fail-closed at every layer.

A bad upstream day can delay an update. It cannot corrupt your docs. These guards exist because a broken sitemap once tried to delete most of the documentation in a single sync.

Discovery floorToo few pages found means a broken source, never "these pages are gone". The run aborts before anything is written.
Removal ceilingA manifest transition that drops too large a share of live pages is refused instead of committed.
Carry-forwardA page that fails to fetch stays in the manifest marked stale. A transient error never drops a page.
Independent CI re-checkEvery rule is re-run as a jq check before commit, pinned to the Python constants by tests. Bypassing one layer is not enough.
Hardened clientDomain allowlist, HTTPS-only with no redirects, atomic writes, sha256 integrity checks, path-traversal protection. 230+ automated tests on Linux and macOS.
